# src/nav

Part of the root `CLAUDE.md` (Layout), kept here so it loads with this directory.

- `src/nav/`: macOS-style menu bar (`Nav.tsx`), `NavMenuItem` with `action` / `widget` / `href`, actions in `navActions.ts`, keyboard shortcuts in `shortcuts.ts`, the View menu (layouts), and the About, Clock, Fullscreen and channel indicators, `actions/UnitRequestIndicator` (hidden without a units server: a bell with the pending requests' count, warning-colored while one is pending, red for a 0; its menu acknowledges them one by one and has Show in Window), and `actions/BackupIndicator` (hidden unless the API's backup status is `enabled`, i.e. an instance is configured: an icon colored by `summarizeBackup` whose menu has a heading per instance (its own summary dot and error) with its jobs below, each with state and last run; clicking a job shows its targets with state and error below it; and Refresh). Menus follow missioncontroller's: Missions (Map, Save ⌘S via `widgets/MissionDetails/missionSave.ts`, Clear, Close via `MissionCloseProvider`, which PATCHes `status: closed`; there is no reopen; Intermediate Report… ⌘P (action `printMission`) via `MissionPrintProvider`, whose `IntermediateReportDialog` picks an export template, POSTs `/api/v1/missions/{id}/intermediate-report` (`intermediateReport` in `api/exportTemplates.ts`) for a mission in any status, and opens the PDF in a `PdfViewer` window. The API sets the template variable `is_intermediate`, watermarks every page and records the report as an `intermediate_report` audit entry of the mission, not as a Report, so the dialog fetches once per submit and hands the blob over through `shared/pdfDocuments.ts`; Create Report…, enabled for a done or closed selected mission, opens the window-only `CreateReport` widget with that `missionId` fixed; Reports), Units (Unit Status, Unit Requests, Unit Scopes, Units in Mission, Add Unit…), Logbook, Admin (admins only: the admin widgets, Map Styles, Export Templates and Layouts included), View, Help.
