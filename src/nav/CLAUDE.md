# src/nav

Part of the root `CLAUDE.md` (Layout), kept here so it loads with this directory.

- `src/nav/`: macOS-style menu bar (`Nav.tsx`), `NavMenuItem` with `action` / `widget` / `href`, actions in `navActions.ts` (`mobileView`, Universam → Responsive View, is disabled when the session's user function has no responsive view), keyboard shortcuts in `shortcuts.ts`, the View menu (layouts), and the About, Clock, Fullscreen and channel indicators (About: the user and groups, and Versions: the frontend build (`__APP_VERSION__` / `__APP_COMMIT__` / `__APP_BUILD_TIME__`), the API's (`useApiVersion`) and, from `/api/v1/connections` and the backup status, each connected service's and backup instance's `version`, 'unknown' when it tells none), `actions/ConnectionsIndicator` (beside the live indicator; hidden while the API reports no configured service: a hub icon green when every server is connected, warning-colored when some and red when all are disconnected, dimmed while one is still being checked; its menu lists each server (`serviceLabel`) with a dot, since when and the API's short reason, plus Refresh), `actions/UnitRequestIndicator` (hidden without a units server: a bell with the pending requests' count, warning-colored while one is pending, red for a 0; its menu acknowledges them one by one and has Show in Window), `actions/MessageIndicator` (hidden without `messages.view`: a chat icon with the count of messages the session's function has yet to acknowledge as To (`useUnacknowledgedMessages`), warning-colored while one is pending, red for a priority I; a click opens the Messages widget on the unacknowledged ones), `actions/MessageToasts` (below the menu bar: a toast per message that arrives in the function's inbox, To or CC, after the first load (`useMessageArrivals` in `data/messages.ts`, `arrivedMessages`: one a live `messages` event brought that the previous list lacked); priorities I and II stay until dismissed, III and IV close after 8 s (`toastTimeout`); Open shows it in the Messages widget (option `messageId`)), and `actions/BackupIndicator` (hidden unless the API's backup status is `enabled`, i.e. an instance is configured: an icon colored by `summarizeBackup` whose menu has a heading per instance (its own summary dot and error) with its jobs below, each with state and last run; clicking a job shows its targets with state and error below it; and Refresh). Menus follow missioncontroller's: Missions (Map, Save ⌘S via `widgets/MissionDetails/missionSave.ts`, Clear, Close via `MissionCloseProvider`, which PATCHes `status: closed`; there is no reopen; Intermediate Report ⌘P (action `printMission`) via `MissionPrintProvider`, whose `IntermediateReportDialog` picks an export template, POSTs `/api/v1/missions/{id}/intermediate-report` (`intermediateReport` in `api/exportTemplates.ts`) for a mission in any status, and opens the PDF in a `PdfViewer` window. The API sets the template variable `is_intermediate`, watermarks every page and records the report as an `intermediate_report` audit entry of the mission, not as a Report, so the dialog fetches once per submit and hands the blob over through `shared/pdfDocuments.ts`; Create Report, enabled for a done or closed selected mission, opens the window-only `CreateReport` widget with that `missionId` fixed; Reports), Units (Unit Status, Unit Requests, Unit Scopes, Units in Mission, Add Unit), Logbook, Messages (with `messages.view`: Messages ⌥⇧M, Message Tags), Admin (shown to the admin group and to anyone holding a personal permission of its widgets, `adminMenuPermissions`: the admin widgets, User Functions and Sessions included), View, Help. A widget item the caller may not use (the registry's `adminOnly` / `permission`) and an action without its permission (Save: `missions.edit`, Close: `missions.manage`, Create Report: `missions.edit`) are disabled (`navItem.ts`, `navActions.ts`). `actions/SessionMenu` (instead of the old scope menu) shows the session's function and scope and opens `SessionDialog` to switch them. `actions/ScopeUsersIndicator` (before it; hidden by an API without the endpoint): a people icon with the number of users signed in to the session's scope; its menu lists each session there (user, function, an UHS chip, since when, the own one marked) and Refresh, from `GET /api/v1/sessions/current/scope` (`fetchScopePeers`, no permission needed, no session IDs), polled every 30 s while online and reloaded after a switch, since sessions are not on the event stream.
