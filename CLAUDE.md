# universamFrontend

Vite + React 19 (TypeScript) single-page application. Its base structure is copied from `missioncontroller/web`, without domain widgets. It is the frontend of `universalGoApi`, which runs on a separate origin.

## Layout

- `src/main.tsx` renders `app/App.tsx`, the auth gate. Once signed in it renders `app/Shell.tsx`: `ResourceProvider` → `EventsProvider` → `DataProvider` → `LayoutProvider` → `DashboardProvider` → `SelectedMissionProvider` → `WidgetWindows` → `Nav` + `Dashboard`.
- Routing (React Router, `react-router`): the `BrowserRouter` is mounted in `App.tsx` only once signed in, as `startSession` may first replace the URL with the login's return path. `/m/*` renders `responsive/ResponsiveShell.tsx`, everything else the desktop `Shell`. `main.tsx` sends small touch screens opening `/` to `/m` (before the session starts, so a login returns there) unless `localStorage` `universam.preferDesktop` is set (`app/mobileRoute.ts`) (set by the responsive Settings page's Desktop view); the desktop's Universam → Responsive View (action `mobileView`) clears it.
- `src/responsive/`: the responsive UI under `/m` (phones and tablets), independent of the dashboard: `AppFrame`, its pages (missions, mission, new mission, map, archive, reports, settings) and the MUI variants of the widgets it shows (`@mui/material` 9; the desktop does not use MUI). Details: `src/responsive/CLAUDE.md`.
- Auth (`src/auth/session.ts`, oidc-client-ts):
  1. The login page offers Authentik or a client certificate. The certificate button calls `GET /api/v1/whoami` without a token on the mTLS API URL; a 200 means an mTLS reverse proxy authenticated the certificate (`mode: 'proxy'`), and that URL is used from then on. The choice is kept in sessionStorage (`universam.clientCertificate`) so a reload re-checks it instead of showing the login page; Log Out and any 401 forget it. The mTLS URL is never contacted without the button, since a browser may prompt for a certificate.
  2. Otherwise it uses the Authentik authorization code + PKCE flow, configured from `GET /auth/config`. The redirect URI is `<origin>/callback`, and tokens are kept in sessionStorage.
  3. Tokens are renewed in the background with the refresh token, which needs the `offline_access` scope in the API's `OIDC_SCOPES`. Without one, the session ends when the token expires. `session.ts` renews it itself (oidc-client-ts's `automaticSilentRenew` is off): a timer fires ahead of expiry, by half the token's lifetime but at most 2 min. A network error is retried with backoff (5–60 s). It checks again on `focus`, `online` and when the tab becomes visible, since timers run late in background or sleeping tabs. `send()` in `client.ts` waits for a renewal (`setTokenRefresh`) before a request whose token has expired. Only one renewal runs at a time, because Authentik rotates refresh tokens.
  4. Logging out uses the provider's `end_session_endpoint`.
  5. Any 401 shows the login page again.
- `useSession()` (`app/session.ts`) returns `{ principal, mode, logout }`. `isAdmin(principal)` / `useIsAdmin()` read `permissions` from whoami (`admin` for members of the API's `ADMIN_GROUP`; absent = none).
- `src/api/`: `client.ts` (`request`, `requestBlob`, the API URL from `/config.json`, `ApiError`), `resource.ts` (`useResource`, a shared coalescing cache), `EventsProvider.tsx` + `events.ts` (live updates over a WebSocket; a new API entity type needs an entry in `typePaths`), and one module per entity (missions, logbook, units, reports, catalogs, maps, backup, …). Details: `src/api/CLAUDE.md`.
- `src/data/`: API data for widgets and the responsive UI: catalogs, missions synced per status from the replica, mission scopes and the tab's selected scope, `useMission`, `useSelectedMission`, `useMissionData`. Details: `src/data/CLAUDE.md`.
- `src/components/`: generic UI (`Alert`, `Spinner`, `ConfirmDialog`, `SuggestInput`, `form/`, `menu/`, `symbols/`, `widgetWindow/`).
- `src/nav/`: the macOS-style menu bar (`Nav.tsx`), its menus, actions (`navActions.ts`), shortcuts (`shortcuts.ts`) and indicators (live, unit requests, backup). Details: `src/nav/CLAUDE.md`.
- `src/pages/dashboard/`: the layout framework (built-in layout in `dashboard.json`, layouts stored by the API, edit mode, multi-monitor arrangements, channels). Details: `src/pages/dashboard/CLAUDE.md`.
- `src/pages/dashboard/widgets/`: `registry.ts`, the widgets and their `shared/` parts. The `selection` (`selectedId`) is a mission ID; a closed mission is read-only in every widget. Details: `src/pages/dashboard/widgets/CLAUDE.md`.
- PWA (`vite-plugin-pwa`, configured in `vite.config.ts`): a Workbox service worker precaches the app's own build output, OCR assets in `/ocr/` included (~21 MB; `maximumFileSizeToCacheInBytes` 8 MiB). The Material Symbols font is a subset made by `scripts/subset-icon-font.mjs` (on `predev`/`prebuild`, into the ignored `src/styles/generated/`, loaded by `src/styles/symbols.css`): every icon, weight/grade/optical size pinned to 400/0/24 and FILL kept, ~330 kB instead of 4 MB, so an icon needs weight 400 and a new axis use needs the script, and serves `index.html` for navigations (not `/api/`, `/auth/`). It caches no API data (the app keeps its own, see Offline mode); `/config.json` is NetworkFirst (cache `config`) so the last copy works offline; map styles, sprites, glyphs and tiles (every other origin except `/api/`, `/auth/` and Authentik's `/application/`, `/if/` paths, plus `/api/v1/overlays/`) are StaleWhileRevalidate in cache `map-tiles` (24 h, 3000 entries). `registerType: 'prompt'`: `app/update/UpdatePrompt.tsx`, mounted in `App.tsx` (login page included), shows a Later/Reload notice when a new build is found (on page load only), with `responsive/UpdatePromptMUI.tsx` (lazy, a top Snackbar) on `/m`. The manifest (`start_url: /m`, theme `#1976d2`) and its icons are generated at build from `public/favicon.svg` (`pwaAssets`). No service worker in `make dev`.
- Offline mode (read-only): `api/connectivity.ts` decides when the app is offline; `api/offlineStore.ts` (IndexedDB) and `api/replica.ts` replicate the mission domain and keep file contents, so the app shows the last data and refuses writes. Details: `src/api/CLAUDE.md`.
- `src/styles/`: design tokens and global partials (copied from missioncontroller, `_logbook.scss` included), pulled in by `src/index.scss`. Components use `*.module.scss`; forms are in the Mission Details style (`components/form`: `Section`, `FieldRow`, `FormActions`, errors below the actions).
- `@/` is an alias for `src/`.

## Conventions

- Context: `createContext<T | null>(null)`, read with `use()` in a hook that throws outside its provider.
- Comments explain why. Don't restate names.
- The details of `src/api/`, `src/data/`, `src/nav/`, `src/responsive/`, `src/pages/dashboard/` and its `widgets/` are in each directory's own `CLAUDE.md`; a change there updates that file, and this one only when the summary changes.
- Adding a widget: create `widgets/<Name>/<Name>.tsx` (default export taking `WidgetProps`), register it in `registry.ts`, and optionally add a `NavMenuItem` and shortcut.

## Commands

- `make dev`: Vite dev server on port 5173 (fixed, because the redirect URI and CORS depend on it). The API is at `VITE_API_BASE_URL` (`.env.development`: `http://localhost:8080`).
- Authentik: register `http://localhost:5173/callback` (and the production `<origin>/callback`) as redirect URIs. Add the SPA origin to the API's `CORS_ALLOWED_ORIGINS`.
- `make build`: `tsc -b && vite build` into `dist/`.
- `make lint` (oxlint; warnings fail), `make fmt` / `make fmt-check` (Prettier, `.prettierrc.json`).
- `make test`: Vitest (`vitest.config.ts`, node environment; IndexedDB from `fake-indexeddb`). Tests sit next to the module as `*.test.ts` and cover logic without React or the DOM.
- `make docker API_BASE_URL=https://api.example.com`: nginx image that serves `dist/` and falls back to `index.html`. Set the API origin at runtime by mounting a `config.json` (`{"apiBaseUrl": "https://api.example.com", "mtlsApiBaseUrl": "https://mtls.api.example.com"}`) at `/usr/share/nginx/html/config.json`. `API_BASE_URL` is an optional build-time fallback. `nginx-headers.conf` (included in every location, as a location's `add_header` drops the server's) sets nosniff, the referrer policy, `X-Frame-Options`, a Permissions-Policy, an enforced CSP of `frame-ancestors 'none'; base-uri 'self'` and the full CSP as Report-Only; nginx gzips text. The Docker workflow smoke-tests the image (routes, headers, gzip) before pushing.
