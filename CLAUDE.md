# universamFrontend

Vite + React 19 (TypeScript) single-page application. Its base structure is copied from `missioncontroller/web`, without server-sent events or domain widgets. It is the frontend of `universalGoApi`, which runs on a separate origin.

## Layout

- `src/main.tsx` renders `app/App.tsx`, the auth gate. Once signed in it renders `app/Shell.tsx`: `ResourceProvider` → `DataProvider` → `LayoutProvider` → `DashboardProvider` → `SelectedMissionProvider` → `WidgetWindows` → `Nav` + `Dashboard`.
- Auth (`src/auth/session.ts`, oidc-client-ts):
  1. The login page offers Authentik or a client certificate. The certificate button calls `GET /api/v1/whoami` without a token on the mTLS API URL; a 200 means an mTLS reverse proxy authenticated the certificate (`mode: 'proxy'`), and that URL is used from then on. The choice is kept in sessionStorage (`universam.clientCertificate`) so a reload re-checks it instead of showing the login page; Log Out and any 401 forget it. The mTLS URL is never contacted without the button, since a browser may prompt for a certificate.
  2. Otherwise it uses the Authentik authorization code + PKCE flow, configured from `GET /auth/config`. The redirect URI is `<origin>/callback`, and tokens are kept in sessionStorage.
  3. Tokens are renewed with the refresh token, which needs the `offline_access` scope in the API's `OIDC_SCOPES`. Without one, the session ends when the token expires.
  4. Logging out uses the provider's `end_session_endpoint`.
  5. Any 401 shows the login page again.
- `useSession()` (`app/session.ts`) returns `{ principal, mode, logout }`. `isAdmin(principal)` / `useIsAdmin()` read `permissions` from whoami (`admin` for members of the API's `ADMIN_GROUP`; absent = none).
- `src/api/`: `layouts.ts` (dashboard layouts and the user's preferences), `client.ts` (`request` prefixes the API URL from `/config.json`, loaded by `main.tsx` before rendering: `apiBaseUrl` for OIDC (else `VITE_API_BASE_URL`), `mtlsApiBaseUrl` for client certificates (else `apiBaseUrl`); sends `credentials: 'include'` and the Bearer token, throws `ApiError` with the RFC 9457 `detail`), `auth.ts` (`/auth/config`, `/api/v1/whoami`), `directory.ts` (users, groups, members), `audit.ts` (`auditLogPath`), `address.ts` (address suggestions from `/api/v1/address/{streets,house-numbers,cities,districts}`; a 404 turns them off until reload), `resource.ts` (`useResource(path)`: a shared, coalescing cache that loads when first shown and on `reload()`, with no change events), `setting.ts`, `maps.ts` (map styles: `useMapStyles()`, `resolveMapStyle`, `mapStylesApi`; overlays proxied by the API from its tile server: `useOverlays()`, `fetchOverlayBounds`, `overlayTilePath`). `useResource(path, fetcher)` takes an optional module-level fetcher; `list.ts` (`requestAll`, `listFetcher`) follows `next_before` through every page, and `collection.ts` (`useCollection`) turns a list into `{ items, byId, loading, error, reload }`. Types and paths per entity: `entity.ts`, `catalogs.ts` (plus `*Api` create/patch/remove for admins), `missions.ts`, `logbook.ts`, `tasks.ts`, `exportTemplates.ts` (`useExportTemplates()`, `exportTemplatesApi` incl. `preview`, `missionExportPath`), `reports.ts` (`useReports(filter)`, `reportsApi.create`/`sign`, `reportPdfPath`). `/api/v1/users` is readable by every user (the Reports widget names signers with it).
- `src/data/`: API data for widgets. `useCatalogs()` (mission type groups, mission types, logbook types, file types) and `useMissions()` load once signed in. `useSelectedMission()` gives `{ mission, logEntries, logFiles, tasks }` for the dashboard's `selectedId` (mission null if it isn't a mission). `useMissionData(id)` gives the same for any other mission. The admin endpoints (users, groups, audit log) are loaded only by the admin widgets. Nothing refreshes by itself: call `reload()` after a write.
- `src/components/`: generic UI (`Alert`, `Spinner`, `ConfirmDialog`, `SuggestInput`, `form/`, `menu/`, `symbols/`, `widgetWindow/`).
- `src/nav/`: macOS-style menu bar (`Nav.tsx`), `NavMenuItem` with `action` / `widget` / `href`, actions in `navActions.ts`, keyboard shortcuts in `shortcuts.ts`, the View menu (layouts), and the About, Clock, Fullscreen and channel indicators. Menus follow missioncontroller's: Missions (Map, Save ⌘S via `widgets/MissionDetails/missionSave.ts`, Clear, Close via `MissionCloseProvider`, which PATCHes `status: closed`; there is no reopen; Print ⌘P via `MissionPrintProvider`, whose `PrintDialog` picks an export template and opens the PDF in a `PdfViewer` window; Create Report…, enabled for a done or closed selected mission, opens the window-only `CreateReport` widget with that `missionId` fixed; Reports), Logbook, Admin (admins only: the admin widgets, Map Styles, Export Templates and Layouts included), View, Help.
- `src/pages/dashboard/`: the layout framework. The built-in layout is in `dashboard.json`. Layouts are stored by the API (`api/layouts.ts`, `/api/v1/layouts`): `global` ones (shown as Shared) are seen and used by everyone, `group` ones by the members of their `groups` (group names as in whoami's `groups`); both are written by admins. `user` ones exist only for their owner. Admins choose who sees a layout with `ShareDialog` (View → Share…, or Share… in the Layouts widget): personal, everyone, or groups picked from `/api/v1/groups` or typed; the edit bar's scope picker switches between personal and everyone. Each user's default layout, the same in every browser, is `default_layout_id` of `/api/v1/me/preferences` (View → Use as My Default; null = the built-in layout). Layouts an older version kept in localStorage (`universam.layouts`, with the browser's default) are uploaded as the user's own on sign-in and then removed (`localLayouts.ts`). There is an edit mode with undo/redo and import/export, multi-monitor arrangements, and channels (BroadcastChannel) that share the `selection` event (`selectedId` in `dashboardContext`).
- `src/pages/dashboard/widgets/`: `registry.ts` (metadata plus a `lazy()` component per widget), `widget.ts`, `widgetOptions.ts`, `widgetCategories.ts`. `Example/` is the template for new widgets. Ported from missioncontroller and adapted to universalGoApi: `MissionsList`, `MissionDetails`, `ActiveMissions`, `Logbook`, `LogbookForm`, `FileList`, `AttachmentViewer` (window only), `Reports` (the reports the caller sees: admins all, others those they created or sign; create from a done or closed mission, upload the signed PDF once with user or external signers), `PdfViewer` (window only; options `path`, an API path, and `name`: printed missions and report PDFs, which need the token, so `shared/blobContent.ts` loads them with `requestBlob`, as for `AttachmentViewer`), `Map` (MapLibre, `maplibre-gl`: missions with `address_coordinates` as pins colored by status, click selects; option `style` (type `mapStyle`) picks a map style by ID, empty = the default; an overlay switcher when the API has a tile server. MapLibre loads the overlay tiles itself, so `transformRequest` adds `authHeaders()` from `api/client.ts` to `/api/v1/overlays/` URLs only). Admin widgets (`adminOnly` + `hiddenInPicker`, opened from the Admin menu; `WidgetContent` shows non-admins a notice instead): `MissionTypes` (groups + types, CSV import/export in `missionTypesCsv.ts`, create-only), `LogbookTypes`, `FileTypes` (all via `shared/CatalogManager`, which reloads the shared `useCatalogs()` collection after a write), `Users`, `Groups` (read-only, LDAP), `MapStyles` (name, https style URL, one default), `ExportTemplates` (pongo2 sources in a CodeMirror editor, `codemirror` + `@codemirror/lang-jinja`, with a live preview of a picked mission through `POST /api/v1/export-templates/preview` in a sandboxed iframe; the variables are listed in `VariablesReference.tsx`), `Layouts` (every user's layouts from `GET /api/v1/layouts?all=true`: rename, Share… (`ShareDialog`), export, history, delete; a write also reloads the View menu's list), `AuditLog` (Newer/Older pages; options `entityType`/`entityId`/`actor` are its starting filter). They link to each other through `openWidget` options. The `selection` (`selectedId`) is a mission ID. A closed mission is read-only in every widget (`readOnly` from `useSelectedMission()`). `shared/` holds their common parts: address autocomplete for Mission Details (`AddressSuggest.ts` + `components/SuggestInput`), `/now`, `/me`, `/callee` commands (`logbookCommands.ts`, `CommandField`), in-browser OCR of attachments (`ocr.ts`, tesseract.js; its assets are copied into `public/ocr/` by `scripts/copy-ocr-assets.mjs` on `predev`/`prebuild`). File content needs the token, so it is loaded with `requestBlob` (`api/client.ts`), never as a plain link. Revoked log entries are not loaded.
- `src/styles/`: design tokens and global partials (copied from missioncontroller, `_logbook.scss` included), pulled in by `src/index.scss`. Components use `*.module.scss`; forms are in the Mission Details style (`components/form`: `Section`, `FieldRow`, `FormActions`, errors below the actions).
- `@/` is an alias for `src/`.

## Conventions

- Context: `createContext<T | null>(null)`, read with `use()` in a hook that throws outside its provider.
- Comments explain why. Don't restate names.
- Adding a widget: create `widgets/<Name>/<Name>.tsx` (default export taking `WidgetProps`), register it in `registry.ts`, and optionally add a `NavMenuItem` and shortcut.

## Commands

- `make dev`: Vite dev server on port 5173 (fixed, because the redirect URI and CORS depend on it). The API is at `VITE_API_BASE_URL` (`.env.development`: `http://localhost:8080`).
- Authentik: register `http://localhost:5173/callback` (and the production `<origin>/callback`) as redirect URIs. Add the SPA origin to the API's `CORS_ALLOWED_ORIGINS`.
- `make build`: `tsc -b && vite build` into `dist/`.
- `make lint` (oxlint), `make fmt` / `make fmt-check` (Prettier, `.prettierrc.json`).
- `make docker API_BASE_URL=https://api.example.com`: nginx image that serves `dist/` and falls back to `index.html`. Set the API origin at runtime by mounting a `config.json` (`{"apiBaseUrl": "https://api.example.com", "mtlsApiBaseUrl": "https://mtls.api.example.com"}`) at `/usr/share/nginx/html/config.json`. `API_BASE_URL` is an optional build-time fallback.
