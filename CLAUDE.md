# universamFrontend

Vite + React 19 (TypeScript) single-page application. Its base structure is copied from `missioncontroller/web`, without domain widgets. It is the frontend of `universalGoApi`, which runs on a separate origin.

## Layout

- `src/main.tsx` renders `app/App.tsx`, the auth gate. Once signed in it renders `app/Shell.tsx`: `ResourceProvider` → `EventsProvider` → `DataProvider` → `LayoutProvider` → `DashboardProvider` → `SelectedMissionProvider` → `WidgetWindows` → `Nav` + `Dashboard`.
- Routing (React Router, `react-router`): the `BrowserRouter` is mounted in `App.tsx` only once signed in, as `startSession` may first replace the URL with the login's return path. `/m/*` renders `responsive/ResponsiveShell.tsx`, everything else the desktop `Shell`. `main.tsx` sends small touch screens opening `/` to `/m` (before the session starts, so a login returns there) unless `localStorage` `universam.preferDesktop` is set (`app/mobileRoute.ts`) (set by the responsive Settings page's Desktop view); the desktop's Universam → Responsive View (action `mobileView`) clears it.
- `src/responsive/`: a responsive UI independent of the dashboard. It shares the data layer (`ResourceProvider` → `EventsProvider` → `DataProvider`, `src/api`, `src/data`), generic components and some widgets, but no dashboard, layouts, `DashboardContext` or selection. `AppFrame` has a header with the `LiveIndicator` and one nav that is a bottom tab bar on phones and a sidebar from 768px. `WidgetSheets` supplies `WidgetWindowContext`: what a widget opens in a window is a full-screen sheet kept in the history entry's state, so Back closes it. `EmbeddedWidget` shows a registered widget in a frame-like card that grows with the page. Routes (relative to `/m`, built with `paths.ts`): `missions` (`pages/MissionsPage`: search and status filter (Active, Done, Closed, All) kept in the URL as `?q=` and `?status=`), `missions/:id` (`pages/MissionPage`: a Show on map link (`paths.missionOnMap`, to `map?mission=`) for a mission with `address_coordinates`, the Mission Details widget's `MissionForm` for the mission in the URL, then the `LogbookForm` (`showMission: false`) and `Logbook` (`showCreate: false`) widgets (stacked; from 1100px the form left, the logbook right), given that mission through `SelectedMissionContext` with `useMissionData(id)`), `map` (`pages/MapPage`, lazy-loaded: the Map widget's `MissionMap` with its default options; tapping a pin keeps the mission in `?mission=` and shows a card linking to its page; it opens on the view it was left at, kept in `localStorage` (`universam.mapView`, `mapView.ts`) through `MissionMap`'s `onViewChange`). `settings` (`pages/SettingsPage`: account details from whoami, Map overlays, Desktop view, Log out). The map's overlays are switched on the Settings page, not on the map: `overlaySettings.ts` keeps them in `localStorage` (`universam.mapOverlays`) and `MapPage` passes them as `overlayControl`. `MissionMap` takes `selectedId`/`onSelect` and an optional `overlayControl` (without it, its own state and switcher, as on the dashboard); the dashboard's `Map` widget wraps it with `useDashboard()`. A new page gets a route in `ResponsiveShell`, a path in `paths.ts` and, if it is a section, an entry in `AppFrame`'s `sections`. Widgets on `/m` are MUI (`@mui/material` 7 + emotion, styled with `sx`; icons stay `SymbolIcon`); the desktop does not use MUI. `src/responsive/widgets/` holds a `<Name>MUI` variant per widget used there (`MissionDetailsMUI` (`MissionFormMUI` only, used by `MissionPage`; the desktop wrapper needs `useDashboard()`), `LogbookFormMUI`, `LogbookMUI` (a visible Revoke button per entry instead of the context menu), `AttachmentViewerMUI`, `PdfViewerMUI`) and their MUI inputs in `shared/`. They import the desktop widgets' hooks and helpers (`useMissionForm`, `useLogbookFormWidget`, `useLogbookWidget`, `logbookCommands`, `useAddressSuggest`, `useBlobContent`, …) and only render differently, so a behavior change goes into the shared hook. `widgets/registry.ts` keys them by the desktop ID, reusing its metadata; `responsiveWidget(id)` (used by `EmbeddedWidget` and `WidgetSheets`) returns the MUI variant, else the desktop widget, so `openWidget('AttachmentViewer')` opens the MUI one on `/m`. The theme (`widgets/theme.ts`, colors from `_tokens.scss`, light/dark by system) is provided by `widgets/ThemeScope.tsx` and, like `MissionFormMUI`, loaded lazily so MUI stays out of the desktop's bundle. `_forms.scss`'s bare `input`/`select`/`textarea` rules skip elements with `Mui*` classes (via `:where`, keeping their specificity), as MUI's dialogs and poppers portal outside any route root.
- Auth (`src/auth/session.ts`, oidc-client-ts):
  1. The login page offers Authentik or a client certificate. The certificate button calls `GET /api/v1/whoami` without a token on the mTLS API URL; a 200 means an mTLS reverse proxy authenticated the certificate (`mode: 'proxy'`), and that URL is used from then on. The choice is kept in sessionStorage (`universam.clientCertificate`) so a reload re-checks it instead of showing the login page; Log Out and any 401 forget it. The mTLS URL is never contacted without the button, since a browser may prompt for a certificate.
  2. Otherwise it uses the Authentik authorization code + PKCE flow, configured from `GET /auth/config`. The redirect URI is `<origin>/callback`, and tokens are kept in sessionStorage.
  3. Tokens are renewed with the refresh token, which needs the `offline_access` scope in the API's `OIDC_SCOPES`. Without one, the session ends when the token expires.
  4. Logging out uses the provider's `end_session_endpoint`.
  5. Any 401 shows the login page again.
- `useSession()` (`app/session.ts`) returns `{ principal, mode, logout }`. `isAdmin(principal)` / `useIsAdmin()` read `permissions` from whoami (`admin` for members of the API's `ADMIN_GROUP`; absent = none).
- `src/api/`: `layouts.ts` (dashboard layouts and the user's preferences), `client.ts` (`request` prefixes the API URL from `/config.json`, loaded by `main.tsx` before rendering: `apiBaseUrl` for OIDC (else `VITE_API_BASE_URL`), `mtlsApiBaseUrl` for client certificates (else `apiBaseUrl`); sends `credentials: 'include'` and the Bearer token, throws `ApiError` with the RFC 9457 `detail`), `auth.ts` (`/auth/config`, `/api/v1/whoami`), `directory.ts` (users, groups, members), `audit.ts` (`auditLogPath`), `address.ts` (address suggestions from `/api/v1/address/{streets,house-numbers,cities,districts,geo-objects}`; the Object field suggests the directory's geo objects, and picking one replaces street, house number, city, district and position, and `reverseGeocode`, the address at a coordinate from `/api/v1/address/reverse` (the nearest address and nearest geo object): a geo object within 25 m (its name and address), else a house number within 50 m, else null; a 404 turns them off until reload), `resource.ts` (`useResource(path)`: a shared, coalescing cache that loads when first shown, on `reload()` and on change events), `EventsProvider.tsx` + `events.ts` (live updates: a WebSocket to `GET /api/v1/events` (`websocketUrl` in `client.ts`) on which the API announces the entity types (table names) that changed; `changedPaths` maps them to API paths and `cache.reloadShown` reloads the shown ones, everything after a reconnect or `resync`. With OIDC the first message is `{"type":"auth","token":…}`, resent after each renewal (`accessTokenRenewed`), as a browser cannot set the Authorization header on a WebSocket; the client certificate proxy authenticates the upgrade itself. It reconnects with backoff; `LiveIndicator` in the menu bar (and the responsive UI's header) always shows the connection state: green when connected, red while disconnected). A new API entity type needs an entry in `typePaths`; unknown types reload everything, `setting.ts`, `maps.ts` (map styles: `useMapStyles()`, `resolveMapStyle`, `mapStylesApi`; overlays proxied by the API from its tile server: `useOverlays()`, `fetchOverlayBounds`, `overlayTilePath`). `useResource(path, fetcher)` takes an optional module-level fetcher; `list.ts` (`requestAll`, `listFetcher`) follows `next_before` through every page, and `collection.ts` (`useCollection`) turns a list into `{ items, byId, loading, error, reload }`. Types and paths per entity: `entity.ts`, `catalogs.ts` (plus `*Api` create/patch/remove for admins), `missions.ts`, `logbook.ts`, `tasks.ts`, `exportTemplates.ts` (`useExportTemplates()`, `exportTemplatesApi` incl. `preview`, `missionExportPath`), `reports.ts` (`useReports(filter)`, `reportsApi.create`/`sign`, `reportPdfPath`). `/api/v1/users` is readable by every user (the Reports widget names signers with it).
- `src/data/`: API data for widgets and the responsive UI. `useMissionTypeName(id)` gives "Group / Type". `useCatalogs()` (mission type groups, mission types, logbook types, file types) and `useMissions()` load once signed in. `useSelectedMission()` gives `{ mission, logEntries, logFiles, tasks }` for the dashboard's `selectedId` (mission null if it isn't a mission). `useMissionData(id)` gives the same for any other mission. The admin endpoints (users, groups, audit log) are loaded only by the admin widgets. Changes made elsewhere arrive through the event stream; still call `reload()` (or `cache.put`) after a write, so the writer sees it without waiting for the event.
- `src/components/`: generic UI (`Alert`, `Spinner`, `ConfirmDialog`, `SuggestInput`, `form/`, `menu/`, `symbols/`, `widgetWindow/`).
- `src/nav/`: macOS-style menu bar (`Nav.tsx`), `NavMenuItem` with `action` / `widget` / `href`, actions in `navActions.ts`, keyboard shortcuts in `shortcuts.ts`, the View menu (layouts), and the About, Clock, Fullscreen and channel indicators. Menus follow missioncontroller's: Missions (Map, Save ⌘S via `widgets/MissionDetails/missionSave.ts`, Clear, Close via `MissionCloseProvider`, which PATCHes `status: closed`; there is no reopen; Intermediate Report… ⌘P (action `printMission`) via `MissionPrintProvider`, whose `IntermediateReportDialog` picks an export template, POSTs `/api/v1/missions/{id}/intermediate-report` (`intermediateReport` in `api/exportTemplates.ts`) for a mission in any status, and opens the PDF in a `PdfViewer` window. The API sets the template variable `is_intermediate`, watermarks every page and records the report as an `intermediate_report` audit entry of the mission, not as a Report, so the dialog fetches once per submit and hands the blob over through `shared/pdfDocuments.ts`; Create Report…, enabled for a done or closed selected mission, opens the window-only `CreateReport` widget with that `missionId` fixed; Reports), Logbook, Admin (admins only: the admin widgets, Map Styles, Export Templates and Layouts included), View, Help.
- `src/pages/dashboard/`: the layout framework. The built-in layout is in `dashboard.json`. Layouts are stored by the API (`api/layouts.ts`, `/api/v1/layouts`): `global` ones (shown as Shared) are seen and used by everyone, `group` ones by the members of their `groups` (group names as in whoami's `groups`); both are written by admins. `user` ones exist only for their owner. Admins choose who sees a layout with `ShareDialog` (View → Share…, or Share… in the Layouts widget): personal, everyone, or groups picked from `/api/v1/groups` or typed; the edit bar's scope picker switches between personal and everyone. Each user's default layout, the same in every browser, is `default_layout_id` of `/api/v1/me/preferences` (View → Use as My Default; null = the built-in layout). Layouts an older version kept in localStorage (`universam.layouts`, with the browser's default) are uploaded as the user's own on sign-in and then removed (`localLayouts.ts`). There is an edit mode with undo/redo and import/export, multi-monitor arrangements, and channels (BroadcastChannel) that share the `selection` event (`selectedId` in `dashboardContext`).
- `src/pages/dashboard/widgets/`: `registry.ts` (metadata plus a `lazy()` component per widget), `widget.ts`, `widgetOptions.ts`, `widgetCategories.ts`. `Example/` is the template for new widgets. Ported from missioncontroller and adapted to universalGoApi: `MissionsList`, `MissionDetails`, `ActiveMissions`, `Logbook`, `LogbookForm`, `FileList`, `AttachmentViewer` (window only), `Reports` (the reports the caller sees: admins all, others those they created, sign, or that are shared with them or their groups; create from a done or closed mission, upload the signed PDF once with user or external signers; the creator or an admin shares a report with users and groups via `ShareReportDialog` (`reportsApi.share`, `PUT /api/v1/reports/{id}/shares`; non-admins are offered their own groups, as `/api/v1/groups` is admin-only)), `PdfViewer` (window only; options `path`, an API path loaded with `requestBlob` through `shared/blobContent.ts`, as for `AttachmentViewer` (report PDFs need the token), or `document`, the key of an already fetched intermediate report in `shared/pdfDocuments.ts`, gone after a reload; and `name`), `Map` (MapLibre, `maplibre-gl`: missions with `address_coordinates` as pins colored by status, click selects; the context menu (`MissionMap`'s `onContextMenu`, a right click or long press; the actions in `mapActions.ts` (`useMapActions`), rendered by the dashboard widget and, in MUI, by `/m`'s `MapPage`, where the selected mission is `?mission=`) creates a mission at the clicked position (asking for the occurred event) and selects it, or sets the selected mission's `address_coordinates` there (not for a closed one); opening the menu reverse-geocodes the position, and a found address replaces street, house number, city and district, and a found geo object also the object name (without one, it stays); option `style` (type `mapStyle`) picks a map style by ID, empty = the default; an overlay switcher when the API has a tile server. MapLibre loads the overlay tiles itself, so `transformRequest` adds `authHeaders()` from `api/client.ts` to `/api/v1/overlays/` URLs only). Admin widgets (`adminOnly` + `hiddenInPicker`, opened from the Admin menu; `WidgetContent` shows non-admins a notice instead): `MissionTypes` (groups + types, CSV import/export in `missionTypesCsv.ts`, create-only), `LogbookTypes`, `FileTypes` (all via `shared/CatalogManager`, which reloads the shared `useCatalogs()` collection after a write), `Users`, `Groups` (read-only, LDAP), `MapStyles` (name, https style URL, one default), `ExportTemplates` (pongo2 sources in a CodeMirror editor, `codemirror` + `@codemirror/lang-jinja`, with a live preview of a picked mission through `POST /api/v1/export-templates/preview` in a sandboxed iframe, optionally as an intermediate report (`is_intermediate`, with the watermark); the variables are listed in `VariablesReference.tsx`), `Layouts` (every user's layouts from `GET /api/v1/layouts?all=true`: rename, Share… (`ShareDialog`), export, history, delete; a write also reloads the View menu's list), `AuditLog` (Newer/Older pages; options `entityType`/`entityId`/`actor` are its starting filter). They link to each other through `openWidget` options. The `selection` (`selectedId`) is a mission ID. A closed mission is read-only in every widget (`readOnly` from `useSelectedMission()`). `shared/` holds their common parts: address autocomplete for Mission Details (`AddressSuggest.ts` + `components/SuggestInput`), `/now`, `/me`, `/callee` commands (`logbookCommands.ts`, `CommandField`), in-browser OCR of attachments (`ocr.ts`, tesseract.js; its assets are copied into `public/ocr/` by `scripts/copy-ocr-assets.mjs` on `predev`/`prebuild`). File content needs the token, so it is loaded with `requestBlob` (`api/client.ts`), never as a plain link. Revoked log entries are not loaded.
- `src/styles/`: design tokens and global partials (copied from missioncontroller, `_logbook.scss` included), pulled in by `src/index.scss`. Components use `*.module.scss`; forms are in the Mission Details style (`components/form`: `Section`, `FieldRow`, `FormActions`, errors below the actions).
- `@/` is an alias for `src/`.

## Conventions

- Context: `createContext<T | null>(null)`, read with `use()` in a hook that throws outside its provider.
- Comments explain why. Don't restate names.
- Adding a widget: create `widgets/<Name>/<Name>.tsx` (default export taking `WidgetProps`), register it in `registry.ts`, and optionally add a `NavMenuItem` and shortcut.

## Commands

- `make dev`: Vite dev server on port 5173 (fixed, because the redirect URI and CORS depend on it). The API is at `VITE_API_BASE_URL` (`.env.development`: `http://localhost:8080`).
- Authentik: register `http://localhost:5173/callback` (and the production `<origin>/callback`) as redirect URIs. Add the SPA origin to the API's `CORS_ALLOWED_ORIGINS`.
- `make build`: `tsc -b && vite build` into `dist/`.
- `make lint` (oxlint), `make fmt` / `make fmt-check` (Prettier, `.prettierrc.json`).
- `make docker API_BASE_URL=https://api.example.com`: nginx image that serves `dist/` and falls back to `index.html`. Set the API origin at runtime by mounting a `config.json` (`{"apiBaseUrl": "https://api.example.com", "mtlsApiBaseUrl": "https://mtls.api.example.com"}`) at `/usr/share/nginx/html/config.json`. `API_BASE_URL` is an optional build-time fallback.
